01 / About

Writing firmware where code meets hardware

I'm a Carleton University MEng graduate in Electrical Engineering with hands-on experience in embedded firmware development, bare-metal C, and peripheral integration. I've developed firmware on STM32F407 (ARM Cortex-M4) targeting GPIO, UART, ADC, DAC, DMA, and PWM — and debugged real hardware issues like HardFaults, port conflicts, and DMA restart logic along the way.

My undergraduate work at CHARUSAT gave me strong foundations in electronics and communication engineering (CGPA 8.91). From implementing MQTT-based IoT systems on ESP8266 to designing RTL-level processors in Verilog, I've worked across the full hardware-software stack.

I'm drawn to the layer where a single register write controls a physical voltage level and timing matters in nanoseconds. My goal is to build embedded systems that are reliable, efficient, and genuinely close to the metal.

Embedded Firmware Featured
STM32 Embedded Systems: Full Peripheral Stack
A progressive, hands-on firmware portfolio targeting the STM32F407G-DISC1 (ARM Cortex-M4, 168 MHz). Covers the full driver stack from HAL abstraction to bare-metal register access against RM0090 - with zero reliance on generated code at the lower levels. Every project targets a real hardware problem, verified with a logic analyzer or oscilloscope. Debugged real faults: voltage divider pull resistor conflicts, ISR timing races, and DMA restart edge cases.
•Custom I2C driver + logic analyzer verification of every transaction
•Bare-metal TRNG via direct register casting - no HAL, no CubeMX
•USB DFU bootloader jump via .noinit section & VTOR remapping
•DMA UART RX in Normal & Circular modes with ISR-to-mainloop bridging
•Portable I2C library with handler/struct abstraction - reusable across targets
•PWM breathing LED with runtime duty cycle control via timer compare
